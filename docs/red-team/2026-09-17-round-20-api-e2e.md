## Threat model

- Attacker CAN send requests to a ZAYNOR API instance reachable on its bound
  interface and control request JSON and chat text.
- Attacker CANNOT modify ZAYNOR code, the configured output directory, the
  authoritative seal, or the local Ollama process.
- A deployment that deliberately binds the API to a public interface without
  authentication is a separate deployment risk, not assumed here.

## Findings

### RT20-01 — Unbounded chat request body amplification

**Severity:** Medium  **Epistemic level:** CONFIRMED BY INDUCTION
**Bucket:** software vulnerability / resource exhaustion

- **Expectation violated:** malformed or hostile request bodies should be
  rejected at the API boundary before expensive parsing and narration.
- **Abduction:** `ChatRequest` validates types but defines no upper bound for
  `messages` or `ChatMessage.content`. The cheapest competing explanation was
  that an upstream body limit or Pydantic constraint supplied the bound.
- **Deduction:** a 2 MiB message and 10,000 messages should be rejected if a
  request-size control exists at the model boundary.
- **Induction:** executed against commit `1500e28`:

  ```text
  env PYTHONPATH=src python - <<'PY'
  from zaynor.api import ChatRequest
  payload = {"messages": [{"role": "user", "content": "x" * (2 * 1024 * 1024)}]}
  request = ChatRequest.model_validate(payload)
  print(len(request.messages[0].content))
  print(len(ChatRequest.model_validate({"messages": [{"role":"user","content":"x"}] * 10000}).messages))
  PY
  ```

  Observed: `2097152` content bytes and `10000` accepted messages.
- **Causal chain:** attacker-controlled JSON → unbounded Pydantic model →
  unbounded parsing/prompt construction → memory/CPU pressure and possible
  Ollama work amplification.
- **Threat-model precondition:** the attacker must be able to reach the API;
  this is relevant if a server is bound beyond loopback or shared by multiple
  local users.

## Recommendations

Add explicit bounded request validation for message count, role/content size,
and total chat text before case extraction or Ollama invocation. Preserve the
OpenAI error shape and document the selected limits. No scorer, seal, or
authoritative schema change is needed.
