02
01 · El problema
Investigar es reconstruir con evidencia rota
Un modelo de IA ayuda mucho a investigar un incidente: correlaciona artefactos, encuentra inconsistencias, formula hipótesis y sugiere qué conviene mirar después. Usamos modelo basado en ciencia: ABDUCCIÓN-DEDUCCIÓN-INDUCCIÓN
Y también se equivoca. O alucina. Por eso la mantenemos fuera del veredicto. La IA local narra, asiste, ayuda, pero no puede cambiar lo que el motor matemático sella.
En DFIR, una respuesta convincente no es evidencia.
El problema
03
Tres cosas que no deberían llegar a un expediente
Correlación espuria
Muchos artefactos que derivan de la misma fuente no son corroboración independiente.
Ninguna de las tres debería convertirse en una conclusión forense.
Alucinación
Una afirmación fluida, bien escrita y sin nada atrás que la sostenga.
Instrucción adversarial
Texto escondido dentro de un artefacto que le habla al modelo en vez de describir un hecho.
La IA decide qué investigar. La evidencia verificada decide qué puede afirmarse.
Esa frontera no es una recomendación de uso: es la arquitectura del sistema.

05
ZAYNOR reúne tres cosas que suelen estar separadas
Core forense
  • Ingesta de bundles, raw evidence y casos postmortem
  • Normalización, provenance y freeze del caso
  • Análisis determinista con VIGÍA
  • Resultado sellado, audit trail e informes y SHA 256
Investigación asistida
  • Modelo local con Ollama
  • Consultas read-only con policy gate
  • Tres MCP locales: VIGÍA, CRONOS y MNEME
  • Hallucination guard sobre la narración
Interfaces
  • CLI completa
  • API local compatible con OpenAI
  • OpenWebUI y web junior / senior
  • Reportes MD, HTML y PDF
Modelo de autoridad: dos planos separados
Plano autoritativo
  1. bundles / raw / Velociraptor
  2. normalización
  3. freeze + provenance
  4. VIGÍA determinista
  5. result.json + result.seal.json
Plano de investigación
  1. agente local (Ollama)
  2. policy gate
  3. consulta read-only
  4. nueva evidencia
  5. vuelve al plano autoritativo
Sólo el plano autoritativo puede cambiar el veredicto. El agente lee una proyección verificada y nunca escribe el resultado.

El motor
09
Qué quiere decir determinista acá
Independencia de evidencia
Artefactos dependientes no cuentan como corroboración independiente sólo por ser numerosos.
Cierre causal
Una hipótesis con cadena causal incompleta puede no sostener un veredicto aunque haya señales fuertes.
Decisión acotada por riesgo
La incertidumbre termina en ABSTAIN o UNKNOWN en vez de rellenarse con una inferencia generativa.
Aritmética exacta
Fraction y Decimal donde la ruta autoritativa exige resultados exactos y comparables. Sin floats, sin probabilidades inventadas.
Cinco estados, y uno de ellos es no saber
MALICE
SUSPICION
BENIGN
UNKNOWN
ABSTAIN
ABSTAIN no significa que el sistema falló. Significa que las condiciones para sostener una conclusión no se cumplen.
La incertidumbre se conserva en vez de pedirle al modelo que complete lo que falta.
El motor
10
Las guardas que sostienen esa frontera
La evidencia es dato, nunca instrucción
Logs, nombres de archivo, documentos y salidas de herramientas no tienen autoridad de instrucción, y esa propiedad sobrevive a las transformaciones.
Hallucination guard
La narración se contrasta con el resultado sellado: un claim que lo contradice se elimina o se rechaza.
Authority guard
La API y la CLI verifican result.json junto con result.seal.json antes de narrar, y no aceptan un veredicto elegido por el request.
Sin fallback sintético
Si el motor falla, falla explícito. No se fabrica un hallazgo de reemplazo para llenar el hueco.

Límites declarados, con número de ficha
L-002
El bundle de evidencia llega a Level 2, no a Level 3: falta la atestación criptográfica del motor.
L-007
El motor determinista no tiene escalón INTENT: su techo es SUSPICION, por diseño heredado.
L-012
El corpus canónico sesga hacia MALICE; se compensa con casos reales y escenarios que terminan en ABSTAIN.
Alcance
No es un SIEM ni un EDR, no hace remediación autónoma y no analiza telemetría en vivo: trabaja sobre evidencia congelada.
Un sistema que no puede nombrar sus propios modos de falla no merece confianza en un expediente.
Honestidad
17
Seguridad y privacidad: todo corre local
La evidencia no sale de la máquina
El modelo corre con Ollama en el equipo del perito. No hay nube, no hay API externa, no hay datos de un caso viajando a un tercero.
Sin red externa por defecto
El enriquecimiento con inteligencia externa está evaluado pero no conectado al runtime local.
Superficie acotada
Path guard, sandbox y herramientas de lectura confinadas al caso, con todo lo consultado registrado en el audit log.
Integridad verificable
Sellos SHA-256, cadena de auditoría con timestamps dentro de las entradas hasheadas, HMAC opcional, verificación de custodia y replay determinista.

De dónde viene ZAYNOR
VIGÍA
Autoridad determinista: hipótesis, causalidad, provenance, incertidumbre, scoring y abstención.
ANNACONDA
Adquisición DFIR: adapter Velociraptor, normalización, evidence windows, manifest y custodia.
ZAYNOR
Contrato común, freeze / seal / audit, frontera de autoridad, Ollama, MCP, API, CLI, web y loop de reanálisis.
La reutilización está documentada: el motor entra por un adapter explícito y ningún tipo interno lo cruza.
